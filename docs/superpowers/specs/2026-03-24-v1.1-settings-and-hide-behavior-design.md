# v1.1 Design Spec — Settings Panel & Smart Hide Behavior

**Date:** 2026-03-24
**Status:** Approved
**Target version:** v1.1.0

---

## Overview

v1.1 transforms Click for Syria from a functional MVP into something that feels like a polished, intentional product. The two pillars are:

1. **Smart hide behavior** — the overlay remembers its state across tabs and sessions, and gives users meaningful control over when it appears.
2. **Settings popup redesign** — the toolbar popup becomes a proper settings panel (Grammarly-style) with global controls, per-site status, and user details.

Underlying both is a new storage architecture that separates global user preferences from per-site local state.

---

## Storage Architecture

### `chrome.storage.sync` — user preferences
Syncs across all Chrome profiles and devices.

```typescript
{
  userName: string,       // used in email/LinkedIn templates
  globalEnabled: boolean  // master on/off switch for the extension
}
```

**Default for `globalEnabled`:** The decision logic checks `globalEnabled === false` (strict equality). On a fresh install, `chrome.storage.sync.get` returns `undefined` for `globalEnabled`, which does not strictly equal `false` — so the overlay injects correctly with no explicit initialization needed.

### `chrome.storage.local` — per-site state
Device-local. Per-site preferences that shouldn't sync across machines.

```typescript
{
  "site:chatgpt.com": {
    dismissed: boolean,            // true = user has actively clicked Hide at least once
    hideUntil: number | null,      // Unix timestamp for "Hide for today" expiry
    permanentlyDisabled: boolean   // true = never show overlay on this domain
  }
}
```

**`dismissed` and `hideUntil` are independent flags.** "Hide for today" sets `hideUntil` only — it does NOT set `dismissed`. This means when the timer expires, the overlay returns to its maximized state on the next visit (the user didn't permanently dismiss it, just snoozed it). Only clicking the "Hide" button in the overlay top bar sets `dismissed: true`.

**Removing `sessionStorage`:** All `sessionStorage.getItem/setItem('click-for-syria-minimized')` usage is removed from `content.tsx`. The initial minimized state now comes exclusively from the `startMinimized` flag in the SHOW_NOTICE message.

### Storage key discipline
All per-site keys use the format `"site:{domain}"` where `domain` is `matchedSite.domain` from `sites.ts` — never the raw `window.location.hostname`. Enforced via helpers in `src/shared/storage.ts`. Never construct `"site:X"` strings outside that module.

### Decision logic — `shouldShowForDomain(domain: string)`

A shared async function in `background.ts` used by **both** the `onUpdated` push handler and the `CHECK_CURRENT_SITE` pull handler:

```
1. globalEnabled === false (strict)       → { show: false }
2. permanentlyDisabled === true           → { show: false }
3. hideUntil is set AND not yet expired   → { show: true, startMinimized: true }
4. dismissed === true                     → { show: true, startMinimized: true }
5. otherwise (first visit OR timer expired) → { show: true, startMinimized: false }
```

Step 5 is the catch-all: it covers both a first-time visitor (no storage entry) and a visitor returning after a "Hide for today" timer has expired (entry exists but `dismissed` is false and `hideUntil` has passed). Both correctly show the overlay maximized.

When `shouldShowForDomain` returns `{ show: false }`, the `onUpdated` handler simply does not send `SHOW_NOTICE`.

### Manifest permissions
`tabs` and `storage` are already declared in `manifest.config.ts`. No manifest changes needed.

## `src/shared/storage.ts` — Helper API

New shared module. Used by both `background.ts` and `content.tsx` — CRXJS bundles it into both entry points automatically since it's imported from both.

```typescript
// Key builder — always use this, never hardcode "site:X" strings
export const siteKey = (domain: string): string => `site:${domain}`;

export interface SiteState {
  dismissed: boolean;
  hideUntil: number | null;
  permanentlyDisabled: boolean;
}

// Returns null if no entry exists for this domain (first visit)
export const getSiteState = async (domain: string): Promise<SiteState | null>

// Read-modify-write: merges update into existing state (or creates new entry)
export const setSiteState = async (domain: string, update: Partial<SiteState>): Promise<void>

// Returns all site entries. Uses chrome.storage.local.get(null) which returns every key
// in local storage. Filters by applying /^site:/ test to the object's keys.
// Returns domain→state map with the "site:" prefix stripped from keys.
export const getAllSiteStates = async (): Promise<Record<string, SiteState>>
```

## Smart Hide Behavior

### Existing controls (clarification)
The current overlay has two dismiss controls:
- **"Hide" link** in the top bar of the expanded overlay (calls `handleHide()`, currently writes to `sessionStorage`)
- **X button** on the minimized floating icon (appears on hover, currently calls `setIsDismissed(true)` directly)

There is no X button on the expanded overlay. This is the complete picture.

### "Hide" link in expanded overlay (behavior change)
Calls `setSiteState(domain, { dismissed: true })` via `storage.ts`, then `setIsMinimized(true)`. The `domain` is already available as the `site` prop passed to `InjectedApp`.

### X button on minimized icon (behavior change)
**Direct dismiss is removed.** X now opens the snooze menu by setting `isSnoozeMenuOpen: true`. The `isDismissed` state is only reached through the snooze menu options.

### Snooze menu

Rendered as a sibling to the minimized icon inside `InjectedApp`, controlled by `isSnoozeMenuOpen` boolean state. Not a modal. Positioned above the icon.

| Option | Storage write | React state |
|--------|--------------|-------------|
| Hide for this session | none | `setIsDismissed(true)` |
| Hide for today | `setSiteState({ hideUntil: Date.now() + 86400000 })` | `setIsDismissed(true)` |
| Hide permanently on this site | `setSiteState({ permanentlyDisabled: true })` | `setIsDismissed(true)` |
| Cancel | none | `setIsSnoozeMenuOpen(false)` |

**"Hide for this session":** React state only. On SPA sites (e.g., ChatGPT) where the content script persists across soft navigations, the dismiss persists for the full page load. On multi-page sites, re-navigation re-injects the content script and the dismiss is gone. Both behaviors are intentional — "session" means "this page load."

**Snooze menu layout:**
- `position: fixed; bottom: 100px; right: 30px` — positions above the icon (icon is at `bottom: 30px` with `height: 60px`, so this is 10px gap above)
- `width: 220px; border-radius: 12px; background: #fff`
- `box-shadow: 0 4px 20px rgba(0,0,0,0.15); padding: 8px 0`
- `z-index: 2147483647`
- Rendered inside the same Shadow DOM root — no overflow clipping issues
- Animation: `opacity 0→1` + `translateY(8px)→translateY(0)`, 150ms ease-out

## Popup Redesign

### Layout

```
┌─────────────────────────────────┐  width: 380px
│  [Logo]      Click for Syria    │  header, 48px height, bottom border #eee
├─────────────────────────────────┤
│  ⚠ Disabled on chatgpt.com      │  conditional — full-width block, 0 height if absent
│     Re-enable →                 │  only if current site permanentlyDisabled: true
├─────────────────────────────────┤
│  Extension enabled    [●      ] │  global on/off toggle
├─────────────────────────────────┤
│  YOUR DETAILS                   │  11px section label, color #999, letter-spacing: 0.08em
│  Your name                      │
│  [_____________________________]│
├─────────────────────────────────┤
│  DISABLED SITES                 │  section — hidden entirely if no disabled sites
│  chatgpt.com      [Re-enable]   │
│  figma.com        [Re-enable]   │
├─────────────────────────────────┤
│  unblocksyria.com ↗             │  footer link
└─────────────────────────────────┘
```

### Context-aware banner

On popup mount:
1. `chrome.tabs.query({ active: true, currentWindow: true })` → get `tab.url` and `tab.id`
2. `new URL(tab.url).hostname.toLowerCase()` → match against `blockedSites` using `hostname === site.domain || hostname.endsWith('.' + site.domain)` (same logic as `background.ts`)
3. If no match → no banner (current tab is not a tracked site)
4. If match → call `getSiteState(matchedSite.domain)` → if `permanentlyDisabled === true` → render banner

**Re-enable action:**
```typescript
await setSiteState(domain, { permanentlyDisabled: false, dismissed: false, hideUntil: null });
// Also send SHOW_NOTICE to the live tab so overlay appears immediately without reload
const site = blockedSites.find(s => s.domain === domain);
chrome.tabs.sendMessage(tabId, {
  type: 'SHOW_NOTICE',
  site: domain,
  contacts: site.contacts,
  startMinimized: false
});
```

This re-enables both for future visits and for the currently open tab. The `tabId` comes from the `chrome.tabs.query` result at mount time.

Re-enabling resets `dismissed`, `hideUntil`, and `permanentlyDisabled` so the overlay returns fully expanded on the next visit.

Animation: banner `opacity 0→1` 150ms on mount.

### Global toggle
Reads `globalEnabled` from `chrome.storage.sync` on mount. Treat missing value as `true`. Toggle writes back to sync. When turned off, background stops injecting via `shouldShowForDomain` step 1. Already-injected overlays on open tabs are not removed. **When re-enabled from the popup, no live tabs are messaged** — the toggle only affects future page loads. This is an acknowledged limitation.

### Disabled sites list
On mount, calls `getAllSiteStates()`, filters for `permanentlyDisabled === true`. Renders one row per domain: domain name left, Re-enable button right. Clicking Re-enable on a row calls `setSiteState(domain, { permanentlyDisabled: false, dismissed: false, hideUntil: null })` and removes the row from the list. The popup does not attempt to message any live tabs from this list — Re-enable from the disabled sites list only affects future visits. (The banner handles the live-tab case for the current active site.)

Section header and rows are not rendered at all when the list is empty.

### Your name
Identical behavior to v1.0.0. `chrome.storage.sync`. "✓ Saved" confirmation on change.

### Footer
`chrome.tabs.create({ url: 'https://unblocksyria.com/en' })` — popup context cannot reliably use `window.open`.

## UI Polish

### Typography
Font stack: `Inter, system-ui, -apple-system, "Segoe UI", sans-serif`. No CDN import — avoids CSP issues in both popup and Shadow DOM. On most machines, `Inter` will not be installed and `system-ui` will be used instead — this is acceptable. The improvement is consistent, explicit font stack declarations across all components rather than the mixed values currently scattered through inline styles and CSS files.

- Weights: 400 (body), 500 (labels/buttons), 700 (headings only)
- Scale: 11px (section labels), 13px (secondary text), 15px (body), 17px (headings)

### Spacing
Base unit: 8px. All padding, margin, gap values are multiples of 8px. Section dividers: `1px solid #eee`. Popup horizontal padding: 16px.

### Animations
- **Minimized icon appear:** `opacity 0→1` + `scale(0.8)→scale(1)`, 200ms ease-out
- **Snooze menu appear:** `opacity 0→1` + `translateY(8px)→translateY(0)`, 150ms ease-out
- **Popup banner mount:** `opacity 0→1`, 150ms
- **`prefers-reduced-motion`:** `@media (prefers-reduced-motion: reduce) { * { transition: none !important; animation: none !important; } }` added to all style blocks (inline CSS in Shadow DOM and `App.css` for popup)

### Color tokens (unchanged)
- Brand green: `#007a33`
- Brand red: `#ce1126`
- Text primary: `#1a1a1a`
- Text secondary: `#666`
- Section labels: `#999`
- Border/divider: `#eee`
- Backgrounds: `#fff` / `#fafafa`

## What This Doesn't Change

- Overlay content, layout, and three action flows (email, LinkedIn, Instagram)
- `sites.ts` data structure
- Push/Pull messaging pattern (both paths updated to include `startMinimized`)
- Manifest generation via CRXJS

## Known Limitations (Acknowledged)

- **Global toggle re-enable** does not show the overlay on already-open tabs. Reload required. Deferred.
- **"Hide for this session"** is more persistent on SPA sites (persists across soft navigations). Intentional.
- **Inter font** only renders if installed on the OS. Falls back to system-ui silently. Acceptable.
